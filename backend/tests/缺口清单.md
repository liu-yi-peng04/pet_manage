# 高风险用例清单

pytest 用一次性 SQLite + FastAPI `TestClient`，不依赖本机 MySQL / Milvus / 大模型。
命令见本文件末尾。原手工脚本 `backend/test_workspace.py` 仍保留，仅作对照，CI 不跑它。

## 已实现

| 场景 | 位置 | 断言 |
|------|------|------|
| 跨店工作台隔离（概览、预约、客户、寄养计数） | `test_workspace_isolation.py` | 200，且只含本店字段 / id |
| 普通用户打开工作台 | 同上 | 403 |
| 本店店员确认预约、确认寄养 | 同上 | 200，列表中状态变为 `confirmed` |
| 跨店改预约 / 改寄养 | 同上 | 404，对方状态不变 |
| 跨店建商品 / 本店建商品 | 同上 | 403 / 200 且 `store_id` 为本店 |
| 普通用户、超管上架商品 | 同上 | 403 |
| 医院拒绝员工分配（旧脚本已过时的行为） | 同上 | 400 |
| 订单合法流转 `pending → accepted → preparing → delivering → completed` | `test_orders_state_machine.py` | 每步 200 且 `status` 匹配 |
| 订单非法跳转、未知状态 | 同上 | 400，状态保持 `pending` |
| 用户改履约状态、他店改单 | 同上 | 403 / 404 |
| 用户取消待处理订单并回滚库存 | 同上 | 200，库存恢复；再次取消 400 |
| 训犬师 train：缺教练、未审核、非用户发起 | `test_trainer_appointments.py` | 400 / 403 |
| 审核后创建、本人收件、他师不可见也不可改 | 同上 | 200 / 404 / 403 |
| 不同用户会话与宠物档案不串 | `test_chat_channel.py` | 历史接口不含对方内容；提示词不含对方过敏原文 |
| 同一用户从 user 通道切到 staff 通道 | 同上 | 不复用旧会话，不带宠物档案 |
| 跨店改/删商品、把商品改挂到他店 | `test_cross_store_writes.py` | 404 / 403 |
| 跨店删待售宠 | 同上 | 404 |
| 非本店客户的疫苗代约 | 同上 | 404 |

聊天用例把 `app.api.chat.agent_service.run_agent_last` 换成回显，避免 CI 访问 DeepSeek。

## 待补

- 流式 `POST /api/chat/stream` 的通道隔离（SSE 事件里的会话 id、增量内容）。非流式准备链路已覆盖。
- Milvus 检索不串库：`kb_id` / 门店内容库过滤。需要向量库，当前测试故意不连。
- 前端按 `userId + channel` 分桶的本地会话缓存。
- 订单并发扣库存、超卖。
- 支付、退款。一期没有第三方支付，取消只回滚库存。
- 预约 / 寄养状态机。接口允许枚举内任意跳转（未知状态才 400），没有订单那种 `NEXT_STATUS`。未把「任意跳转成功」锁成需求。
- 医院代约中转成功路径（本店客户 + 合法医院 + 生成 `exam` 预约），以及医院端自己不能走代约。
- 知识库文档的跨店读写、公共库仅管理员可改。
- 运营线索 `claim` / `match` 的越权。
- 媒体上传的归属与越权读取。
- 预约出参的 `pet_name` / `store_name` / `trainer_name` / `user_name`。`appointment_out` 用 `_rel_str` 判断关联是否已加载，但 Tortoise 模型本身就有可调用的 `filter`，关系字段会被当成未加载，名称恒为 `null`。隔离用例改断言 `pet_id`。这是现有接口行为，本次没有改业务代码。

## 怎么跑

```bash
cd backend
python -m pip install -r requirements-test.txt
python -m pytest
```

`tests/conftest.py` 会把 `DATABASE_URL` 指到 `backend/.pytest.sqlite3`（跑前删掉重建），
不使用环境变量或 `.env` 里的 MySQL。无需启动 uvicorn。

应用运行依赖仍是 `requirements.txt`（含 MySQL、Milvus、本地向量模型）。测试依赖是精简子集，见 `requirements-test.txt`。

CI：`.github/workflows/backend-pytest.yml`。
